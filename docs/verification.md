## SIMD inspection and microbenchmark

`cargo rustc --release --lib -- --emit=asm` shows `uqadd.16b`, `umin.16b`, and `uqsub.16b` in the game movement coordinate pass as well as the standalone dispatch function.

The focused command `bench simd 100000` uses 4096 u8 coordinates, bound 254, alternating increment/decrement, identical starting inputs, black-boxed buffers, release optimization, and elapsed wall time. Both kernels return checksum 518264. Locally the portable source loop took about 7 ms and explicit SIMD dispatch about 12 ms; the compiler may vectorize the portable source baseline after inlining. This confirms equal output and vector instruction emission, not a performance advantage for handwritten SIMD. A four-vector unrolling attempt showed no useful improvement and was discarded. No C++ speedup claim is made.

## Durable Object write-loop repair and unified lobby — November 10, 2026

Published b5e7707c-d1dc-4538-82e2-8de30b94074b without changing namespaces or plans. Root cause: maintain() incremented host generation and returned changed when both the old and next host were null. Every resulting metadata broadcast triggered another client heartbeat; each heartbeat saved two KV entries and reset an alarm. Background clients could therefore create an unbounded loop of SQL writes. Null-to-null maintenance is now stable, and clients do not echo ordinary metadata broadcasts.

Presence/lease snapshots now use server-owned WebSocket attachments, restored after hibernation only when their committed turn, host term and revision match durable storage. Authentication tokens and committed metadata persist together in one state entry. Legacy meta/tokens entries are read for existing rooms. Ordinary heartbeats perform no room storage/alarm writes; actual generation changes still persist for fencing.
